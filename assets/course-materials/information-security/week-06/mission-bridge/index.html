Real-World Case

This happened for real

Nonce reuse is not a theoretical warning — it has broken real cryptosystems in production.

PlayStation 3 signing key (2010)

Sony's PS3 firmware signed code with ECDSA but reused the same nonce value for every signature instead of generating a fresh random one each time. Security researchers (the fail0verflow group, and separately George Hotz) noticed the pattern and used two different signatures that shared a nonce to solve for Sony's private signing key, breaking the PS3's entire code-signing trust chain.

WEP Wi-Fi encryption

WEP used a 24-bit IV (initialization vector) that was short enough to repeat within hours on a busy network. Once an IV/keystream pair repeated, attackers could recover the RC4 keystream and, from there, the network key — a core reason WEP was deprecated in favor of WPA/WPA2.

Lesson: a key + nonce (or IV) pair must be unique, every single time. Reusing it, even once, can leak relationships between plaintexts or, as in the PS3 case, expose the private key itself. Never hard-code a nonce or rely on a counter that can restart at zero for the same key — use a source that guarantees uniqueness for as long as that key is in use.
