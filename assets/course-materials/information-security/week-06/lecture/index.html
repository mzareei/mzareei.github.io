02

Block cipher primitives

The building blocks we need before we get to DES and AES.

The general shape

The block-cipher scheme

Most symmetric encryption schemes are block ciphers: they take a fixed-length plaintext block as input. Later we’ll see how to use them to encrypt input text of arbitrary length.

Plaintext (n bits)+ secret key k
→
Block cipherencryption function
→
Ciphertext (n bits)same length
Symmetric

The same key k is used to decrypt the ciphertext back to plaintext — hence “symmetric” encryption.

Two principles

Confusion and diffusion

We always assume the attacker can see the ciphertext — for example, because it travels over the network and the attacker can capture the packet. We don’t want them to learn anything about the plaintext from it.

🎭

Confusion

An encryption operation where the relationship between the key and the ciphertext is obscured.

Achieved with substitution — think generalized substitution ciphers where each letter can map to any other.

🌊

Diffusion

An encryption operation where the influence of one plaintext bit is spread over many ciphertext bits, hiding the statistical properties of the plaintext.

Achieved with permutation — a letter isn’t just mapped to another letter, it’s spread across “parts” of many 8-bit letters.

Confusion alone isn’t enough — statistical analysis of letters would still work. We need both.

Seeing it happen

One example: substitution, then permutation

Plain text
THIS IS THE END
↓ Substitution
WAIT IT WAS SUN
↓ Permutation
WWII AT TUA NSS

Substitution (confusion) changes each letter’s identity. Permutation (diffusion) reorders those letters — same set of symbols, different position. Notice rows 2 and 3 use exactly the same letters, just reordered.

Why once isn’t enough

Rounds: repeat until every bit matters

Neither confusion nor diffusion alone provides strong enough security. We need to combine them — and do so often enough that a change in one bit ends up affecting every output bit.

Round: a combination of substitution and permutation, repeated as many times as needed so that a bit change affects every output bit.
How it builds up

The first round affects only some parts of the ciphertext; the next round propagates that effect into other parts. Round after round, eventually every bit of the ciphertext is affected.

Confusion = substitution, hides the key↔ciphertext relationship. Diffusion = permutation, spreads one input bit across many output bits. Rounds = repeat both so every output bit ends up affected.

03

DES — the Data Encryption Standard

The most widely used encryption scheme for decades — and the best place to see confusion, diffusion, and rounds working together.

The classic

DES in three numbers

The most widely used encryption scheme is based on the Data Encryption Standard (DES), adopted in 1977 by the National Bureau of Standards — now the National Institute of Standards and Technology (NIST).

1977 / 1979published / standardized
64 bitkey = 56-bit effective + 8-bit parity (every 8th bit)
64 → 64 bit64-bit input, 64-bit output

A DES key occupies 64 bits (8 bytes), but only 56 bits are real key material: the least-significant bit of each byte is a parity bit, so only the top 7 bits of each byte are effective for security.

A Feistel network

One round of DES, in detail

This repeats for i = 1…16; a final swap then produces the 64-bit ciphertext.

Lᵢ = Rᵢ₋₁ Rᵢ = Lᵢ₋₁ ⊕ F(Rᵢ₋₁, Kᵢ)
Why 16 rounds?

With fewer than 16 rounds, DES could be broken by a known-plaintext attack more efficiently than by brute force. With more than 16, it’s a speed trade-off — more rounds, less throughput.

Inside F

The Mangler function

Divide the 32-bit input into 8 chunks of 4 bits. Each chunk is expanded to 6 bits, XORed with a 6-bit key chunk, and then 8 S-boxes each substitute a 6-bit chunk with a 4-bit chunk.

Output: 8 × 4 bits = 32 bits, ready for the final XOR with Lᵢ₋₁.

Encryption’s favorite tool

Why XOR?

Notice

With OR or AND, seeing the output leaks information about the input even without knowing the key. With XOR, every output bit is 50/50 without knowing the key — it leaks nothing on its own, and it is its own inverse.

That “own inverse” property also enables a classic trick: swapping two values without temporary storage.

X := X ⊕ Y
Y := Y ⊕ X
X := X ⊕ Y

The same algorithm, in reverse

Decryption: only the key schedule flips

DES is a Feistel network — encryption and decryption differ only in the round-key order. The same operation sequence is applied with the keys in reverse order.

Decryption roundUses the encryption round key…

At each round, the input is Rₙ₊₁ | Lₙ₊₁ (because of the swap at the end of the encryption rounds). The same algebra verifies the output is Rₙ|Lₙ — and the final swap produces plaintext in the correct order.

The structure isn’t the problem

Security of DES

Recall: the 16 rounds balance resistance to known-plaintext attacks against speed. So where does DES actually break down?

🔑

Key space is too small

256 possible keys — exhaustive key search is relatively easy with today’s computers.

🗝️

S-box design

The design criteria for the S-boxes were kept secret.

🛡️

Sustained resistance

Still, DES proved highly resistant to cryptanalysis techniques published years later.

Discuss

The S-box criteria stayed secret for years, and DES still proved sound against later cryptanalysis. Is security through obscurity always a bad idea, or is this a counterexample?

Stretching the key

Triple DES: running DES three times

To overcome the 56-bit limit, we run DES multiple times, each with a different key.

The standard construction is Encrypt-Decrypt-Encrypt (EDE), per NIST SP 800-67 — so a Triple DES with K1=K2=K3 behaves like a single DES.

Quick check

DES, in your own words

Everyone

Without looking back: (1) how many bits is DES’s effective key?, (2) what differs between encryption and decryption in a Feistel network?, (3) why is Triple DES with K1=K2=K3 backward-compatible with single DES?

Answers

(1) 56 bits. (2) Only the round-key order. (3) Encrypt→Decrypt→Encrypt with the same key cancels itself (Decrypt undoes Encrypt), leaving a single encryption pass.

04

AES — the Advanced Encryption Standard

DES’s replacement — and the symmetric cipher likely protecting your traffic right now.

How we got here

From a public call to a standard

In 1997, NIST put out a public call for a replacement to DES. It narrowed the list to five finalists and ultimately chose an algorithm — Rijndael — now known as the Advanced Encryption Standard (AES).

Nov 2001issued as FIPS 197, replacing DES
128 bitblock size, always
128 / 192 / 256possible key lengths, in bits
Who designed it

Joan Daemen and Vincent Rijmen

Rijndael — the algorithm chosen as AES — was designed by Belgian cryptographers Joan Daemen and Vincent Rijmen. The name “Rijndael” blends their two surnames.
Not a Feistel network

More key, more rounds

Key sizeEncryption rounds
128 bits10
192 bits12
256 bits14
Structural difference

AES does not use a Feistel structure — the block isn’t split into halves where one modifies the other. Instead, it processes the entire block in parallel each round, using substitutions and permutations.

Inside one round

Four stages per round: one permutation, three substitution

The key is expanded into an array of forty-four 32-bit words, w[i]; four words (128 bits) serve as the round key for each round.

SubBytesbyte-by-byte substitution via S-box
→
ShiftRowssimple permutation, row by row
→
MixColumnssubstitution mixing each column
→
AddRoundKeybitwise XOR with the round key

Per FIPS 197, the final round omits MixColumns. The structure is simple, and it’s the same for both encryption and decryption.

Mixing within the column

MixColumns: every byte, a function of its whole column

Apply the MixColumn transformation to each column of the State array — a substitution that alters each byte as a function of all the bytes in that column.

S’0,c = ({02}•S0,c) ⊕ ({03}•S1,c) ⊕ S2,c ⊕ S3,c
S’1,c = S0,c ⊕ ({02}•S1,c) ⊕ ({03}•S2,c) ⊕ S3,c

c ranges over each column (0–3); “•” is multiplication in AES’s finite field, not ordinary multiplication.

05

Encrypting a large message

A block cipher encrypts one block at a time — so how do we encrypt a gigabyte file?

The obvious idea

Break into blocks and encrypt each — is that it?

So far we’ve discussed block ciphers, which take a fixed-length data block as input — 64 bits for DES, 128 bits for AES. What if we want to encrypt a larger message?

  1. We break the message into blocks.
  2. We apply the block cipher to each block.

Is that it? Not quite — how we combine the blocks matters a lot.

The simplest way

ECB mode: each block, on its own

In Electronic Codebook (ECB) mode, plaintext is handled b bits at a time and each block is encrypted independently using the same key.

P1
↓ E, K
C1
P2
↓ E, K
C2
P3
↓ E, K
C3
Why “codebook”

For a given key, there’s a unique ciphertext for every b-bit plaintext block — as if a giant codebook existed with an entry for every possible b-bit pattern.

ECB problem #1

Repeated blocks → repeated ciphertext

If the same b-bit block appears more than once in the message, it always produces the same ciphertext. For long, structured messages, that can be exploitable.

How it’s exploited

If a message is known to always start with certain predefined fields, the cryptanalyst already has known plaintext-ciphertext pairs. If the message has repetitive elements every so many blocks, those elements are identifiable — which can enable substituting or rearranging blocks.

ECB problem #2

No integrity protection across blocks

ECB lacks basic protection against integrity attacks on the ciphertext at the message level (i.e., across multiple cipher blocks).

🔀

Substitution & rearrangement

An attacker can reuse a previously captured ciphertext block to swap out a current one, or reorder the blocks.

🧾

Fabrication of information

The result is a violation of message integrity — specific information can be fabricated without knowing the key.

Chaining the blocks

CBC mode: each block depends on the last

In Cipher Block Chaining (CBC), the input to encryption is the XOR of the current plaintext block with the previous ciphertext block; for the first block we use a random value, the Initialization Vector (IV).

IV ⊕ P1
↓ E, K
C1
C1 ⊕ P2
↓ E, K
C2
C2 ⊕ P3
↓ E, K
C3

↳ each Cᵢ₋₁ feeds the next block — the chain that gives the mode its name.

Why it matters

The input to encryption for each block includes the previous ciphertext block, not just the current plaintext block — so there’s no way to determine one block’s result in isolation. If two plaintext blocks repeat, their ciphertext blocks will differ.

Undoing the chain

CBC decryption — and why the IV needs protecting

Each ciphertext block passes through the decryption algorithm; the result is XORed with the preceding ciphertext block to produce the plaintext block.

Cj = E(K, [Cj−1 ⊕ Pj])
The first block

To produce the first ciphertext block, the IV is XORed with the first plaintext block; on decryption, the IV is XORed with the decryption output to recover the first block. The IV must be known to both sender and receiver — and protected as well as the key.

Why protect it

If an attacker can fool the receiver into using a different IV, they can invert specific bits of the first plaintext block — a violation of integrity, without needing the key.

Reusing CBC for something else

Protecting message integrity with the CBC “residue”

We send only the last block of a CBC encryption — the “residue” — alongside the plaintext (unencrypted).

How it catches tampering

Any modification to the plaintext makes the CBC residue the receiver computes different from the one the sender sent — that ensures integrity, without needing to send every encrypted block.

Combining both goals

What if we want confidentiality and integrity together?

What does NOT work

Simply sending all the CBC blocks (for confidentiality) and also replicating the last block (for integrity) does not work — repeating the same block adds nothing new or different.

🔑🔑

Two separate keys

One key to generate the CBC blocks (confidentiality) and a different one to generate the residue (integrity) — two encryption passes.

🧬

CBC(message ‖ hash of message)

First compute the hash of the message, concatenate it with the message, and apply CBC over the whole thing.

Lesson summary

Symmetric encryption, in one slide

  • We need confusion and diffusion together — and enough rounds for one bit to affect every other bit.
  • DES: 64-bit input, 56-bit key; encryption and decryption are the same algorithm with the round-key sequence reversed.
  • AES: 128-bit input, 128/192/256-bit key; decryption is the inverse of each stage, not a simple Feistel-style reversal.
  • Use Cipher Block Chaining (CBC) to encrypt a large message — don’t just repeat the block cipher unchained (ECB).
  • The last CBC block can serve as a message integrity code (MIC); use different keys for integrity and confidentiality.
One thing to remember

Confuse, diffuse, repeat — and chain the blocks.
