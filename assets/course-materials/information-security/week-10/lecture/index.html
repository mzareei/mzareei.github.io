Defense-in-depth

The firewall is one layer — not the only one.

Prevent · Detect · Survive

Defense-in-depth: three layered goals

→

SurviveBackups, redundancy, incident response — keep operating and recover.
Analogy

Think of building security: the fence and the guard (prevent), the cameras and alarm (detect), the extinguishers and insurance (survive). No single layer is enough. The firewall is the fence — important, but it won't stop someone climbing through an open window.

02

What is a firewall?

Design goals, access policy, capabilities and limits.

Design goals

Firewall design goals

Enforce security policy

  • All traffic between the internal network and the Internet — in both directions — must pass through the firewall.
  • Only traffic authorized by policy is allowed to pass.

Be dependable

  • The firewall itself is immune to subversion.
  • If the guard can be bribed or bypassed, every other rule stops mattering.
Definition

A firewall is a single choke point that inspects and controls traffic crossing the network boundary, enforcing a defined security policy.

Policy first, rules second

Firewall access policy

  • A critical component when planning and implementing a firewall is specifying a suitable access policy.
  • It lists the types of traffic authorized to pass: address ranges, protocols, applications, and content types.
  • It should be developed from the organization's information security risk assessment and policy.
  • Start from a broad specification of which traffic the organization needs, then refine it into filter elements implementable within an appropriate firewall topology.
Rule

Business policy comes first; technical rules are its translation. Rules without policy are just guesses configured by hand.

What it can and can't do

Firewall capabilities and limits

Capabilities

  • Defines a single choke point.
  • Provides a location for monitoring security events.
  • Convenient platform for several non-security Internet functions (e.g., NAT, traffic logging).

Limitations

  • Cannot protect against attacks that bypass it.
  • May not fully protect against internal threats.
  • An improperly secured wireless LAN can be reached from outside.
  • Laptops, tablets, phones, or USB storage infected outside can be used inside.
03

Firewalls & filtering

The core mechanism of every firewall is traffic filtering.

Filtering basics

Packets are checked, then passed

  • The main mechanism in firewalls is traffic filtering.
  • Packets are checked and then passed or discarded.
  • Inbound and outbound affect when the policy is checked.
Think

Why filter outbound traffic and not just inbound? Hint: malware that "phones home," data exfiltration, and compromised machines inside your own network.

What can it decide on?

Filter characteristics a firewall can use

IP address & protocol

Used by packet-filter and stateful-inspection firewalls. Typically to limit access to specific services.

Application protocol

Used by an application-level gateway that relays and monitors the exchange for specific application protocols.

User identity

Typically for inside users who identify themselves using some form of secure authentication.

Network activity

Controls access based on considerations such as time of request, rate of requests, or other activity patterns.

Families of filtering

Filtering types

Packet filtering

  • Access Control Lists (ACLs).
  • Per-packet decision, remembers nothing.

Session filtering

  • Dynamic packet filtering.
  • Stateful inspection.
  • Context-based access control (CBAC).
Key idea

The essential difference: packet filtering looks at each packet in isolation; session filtering remembers the context of the connection a packet belongs to.

Rules & default policies

The packet-filtering firewall

How it works

  • Applies rules to each incoming and outgoing IP packet.
  • A list of rules based on matches in the IP or TCP header.
  • Forwards or discards the packet based on the matching rule.

Filter fields: source IP, destination IP, source/destination transport address (ports), IP protocol field, and interface.

Two default policies

  • Discard (default-deny): prohibit unless expressly permitted. More conservative, controlled, visible to users.
  • Forward (default-allow): permit unless expressly prohibited. Easier to manage but less secure.

Modern best practice: always default-deny.

Example: allow SMTP (email)

Packet-filtering rule table

RuleDirectionSrc addressDest addressProtocolDest portAction
1InExternalInternalTCP25Permit
2OutInternalExternalTCP>1023Permit
3OutInternalExternalTCP25Permit
4InExternalInternalTCP>1023Permit
5EitherAnyAnyAnyAnyDeny
How to read it

Rules 1–4 permit sending and receiving SMTP mail (port 25) and its replies to high ports (>1023). Rule 5 is the default-deny: if nothing matched above, discard. Rules are evaluated top-down; first match wins.

◆ Trace the packet

Which rule matches?

A packet arrives: external source, internal destination, TCP, destination port 25. What happens to it?

RuleDirectionSrcDestProtoPortAction
1InExternalInternalTCP25Permit
Answer

Matches Rule 1 on the first pass → Permit. It's inbound mail to your SMTP server. Because first-match wins, it never reaches rule 5 (deny). Change the port to 23 (Telnet) and it would instead fall through to the default-deny.

Tightening with source port & ACK

Modifying the rules on source ports

RuleDirectionSrcDestProtoDest portActionSrc portACK
1InExternalInternalTCP25Permit>1023—
2OutInternalExternalTCP>1023Permit25—
3OutInternalExternalTCP25Permit>1023—
4InExternalInternalTCP>1023Permit25SET
5EitherAnyAnyAnyAnyDenyAny—
Why

Adding the source port and requiring the ACK bit (rule 4) stops an outside attacker from opening a fresh connection to a high port: ACK is only set on packets that reply to a connection already started from inside. It's a first step toward "stateful" behavior.

Trade-offs

Packet filter: advantages & weaknesses

Advantages

  • Simplicity.
  • Typically transparent to users and very fast.

Weaknesses

  • Can't stop attacks exploiting application-specific vulnerabilities or functions.
  • Limited logging functionality.
  • No advanced user authentication.
  • Vulnerable to TCP/IP protocol bugs (e.g., network-layer address spoofing).
  • Improper configuration can lead to breaches.
Attack → countermeasure

Packet-filter countermeasures

AttackCountermeasure
IP address spoofingDiscard packets with an inside source address if they arrive on an external interface.
Source routing attacksDiscard all packets in which the source specifies the route to take.
Tiny fragment attackEnforce a rule that the first fragment of a packet must contain a predefined minimum amount of the transport header.
Debate

Why would an attacker split a packet into tiny fragments? Hint: if the TCP port information lands in the second fragment, a rule that only inspects the first one might let it through.

05

Stateful inspection

The firewall that remembers who's inside.

Memoryless vs. remembering

Packet filter vs. stateful inspection

Packet filterStateful inspection
Judges each packet in isolation.Remembers active connections.
Stateless — doesn't know if a packet belongs to a legitimate session.Stateful — only admits replies to connections you already started.
Fast and simple, but easier to fool.Slightly more cost, much more security.
Analogy

A packet filter is a guard who checks each ID with no memory. Stateful inspection is a bouncer who remembers who he let in and only lets those already inside leave or be answered.

How it tightens TCP

The stateful inspection firewall

TCP connection directory

  • Tightens TCP rules by creating a directory of TCP connections.
  • There is an entry for each currently established connection.
  • Incoming traffic to high-numbered ports is allowed only if it fits the profile of a directory entry.

State tracking

  • Reviews packet info and also records information about TCP connections.
  • Keeps track of TCP sequence numbers to prevent attacks that depend on the sequence number.

  • Also called an application proxy.

More secure, but slower

Application-level gateway: details

  • Must have proxy code for each application — and may restrict the features supported.
  • Tends to be more secure than packet filters: it understands the protocol, not just headers.
  • Disadvantage: additional processing overhead on each connection.
Modern link

This "understand the protocol" idea is the seed of the next-generation firewall (NGFW) and the WAF, which we'll see at the end. The classic proxy is their direct ancestor.

The hardened guardhouse

Bastion hosts

  • A system identified as a critical strong point in the network's security.
  • Serves as a platform for an application-level gateway.

Secure OS with only essential services; may require user authentication to reach the proxy or host.

Each proxy is small, simple, and checked; restricts features and reachable hosts.

Each proxy is independent and non-privileged.

Limited disk use — hence read-only code.

Analogy

A bastion host is the hardened guardhouse in the DMZ: the only thing exposed to the outside, locked down as much as possible precisely because it's on the front line.

Securing one machine

Host-based firewalls

  • Used to secure an individual host.
  • Available in the OS or as an add-on package; filter and restrict packet flows.
  • Usually implemented on a server.

Tailored

Filtering rules can be tailored to the host environment.

Topology-independent

Protection is provided independent of topology.

Extra layer

Provides an additional layer of protection — defense-in-depth again.

The end-user firewall

Personal firewall

  • Controls traffic between a personal computer or workstation and the Internet or enterprise network.
  • For home or corporate use; typically a software module on a personal computer.
  • Can be housed in the router that connects home computers to a DSL/cable modem or other Internet interface.
  • Typically much less complex than other firewall types.
  • Primary role: deny unauthorized remote access.
  • May also monitor outgoing traffic to detect and block worms and malware activity.
Advanced features

Advanced firewall protection

Two firewalls create a DMZ: public services live in the middle zone, reachable from the Internet but separated from the sensitive internal network.

Why the DMZ exists

DMZ & security monitoring

DMZ

The demilitarized zone hosts servers that must be reachable from the Internet (web, mail, DNS). If one is compromised, the attacker is still trapped outside the internal network, held back by the internal firewall.

Security monitoring

An important aspect of distributed firewall configuration is security monitoring: logs and alerts from each firewall are centralized to detect and correlate incidents across all zones.

Debate

Is the DMZ the "castle moat" of the perimeter model? What happens when your web servers no longer live in your server room but in the cloud? We'll pick this up in the final section.

08

The firewall today

NGFW, WAF, cloud, host — and why the perimeter is changing.

The modern enterprise firewall

Next-generation firewalls (NGFW)

Deep packet inspection

Looks at packet content, not just headers — beyond the classic filter.

App & user awareness

Identifies the actual application (not just the port) and the user behind the traffic.

Integrated IPS

Built-in intrusion-prevention system to block known exploits.

TLS/SSL inspection

Decrypts and inspects encrypted traffic — where almost everything now hides.

Threat intelligence

Live feeds of known-malicious IPs, domains, and signatures.

Examples

Palo Alto, Fortinet (FortiGate), Cisco Firepower, Check Point.

Today's baseline

Stateful inspection is now the minimum, not the advanced option. The NGFW combines the layers we saw — filter, state, and application proxy — into a single device.

Link to Week 3 (OWASP)

Network firewall vs. Web Application Firewall (WAF)

Network firewall / NGFWWeb Application Firewall (WAF)
Operates at network & transport layers (IP, ports, connections).Operates at the HTTP layer (layer 7), inspecting web requests and responses.
Blocks unauthorized ports, IPs, and connections.Filters application attacks: SQLi, XSS, path traversal (the OWASP Top 10).
Doesn't understand "this is a SQL injection attempt."Inspects the HTTP body and parameters to detect malicious payloads.
Not rivals

They complement each other: the network firewall controls who can connect; the WAF controls what the web requests that do arrive can do. Recall the SQLi and XSS attacks from Week 3 — the WAF is a layer built specifically against them.

Where firewalls live now

Cloud & host firewalls in practice

Cloud

AWS Security Groups (stateful) and NACLs (stateless); Azure NSGs. The firewall is now a rule attached to each workload.

Host / Linux

nftables is replacing iptables as the Linux kernel packet filter.

Host / Windows

Windows Defender Firewall: a stateful host-based firewall built into the OS.

Same idea, new place

Same concepts — default-deny, stateful, per port/IP — applied to the host and cloud, not just the perimeter.

# nftables — política por defecto: descartar entrante / nftables: default-drop inbound
nft add rule inet filter input ct state established,related accept
nft add rule inet filter input tcp dport { 22, 443 } accept
nft add rule inet filter input drop  # todo lo demás / everything else

Three classic rules: allow replies to already-established connections (stateful), allow inbound SSH (22) and HTTPS (443), and drop the rest. Equivalent in iptables: -A INPUT -m state --state ESTABLISHED,RELATED -j ACCEPT.

Is the perimeter dead?

Zero Trust & microsegmentation

"Castle-and-moat" model

The perimeter firewall assumes everything inside is trusted. But with cloud, remote work, and mobile devices, there's barely a clear "inside" anymore.

Zero Trust

Never trust, always verify. No implicit trust; identity-based policy is enforced per workload and per request (NIST SP 800-207).

Link to Week 2

Microsegmentation places access controls between internal workloads, not just at the edge — it's access control (Week 2) applied to the network. The classic perimeter firewall is one layer, not the whole story.

◆ Closing debate

Is the network perimeter dead?

With everything in the cloud and remote work, do perimeter firewalls still matter — or does Zero Trust make them obsolete?

One stance

The perimeter isn't dead — it multiplied. Every host, container, and cloud workload now carries its own firewall. The castle-and-moat model alone is no longer enough, but the perimeter firewall remains a valuable defense-in-depth layer. Zero Trust doesn't remove firewalls — it distributes them and ties them to identity.

Summary

Firewalls, in one slide

  • Enforce security policy to prevent attacks by way of traffic filtering; default-deny.
  • Packet filtering (stateless) and session filtering (stateful), plus the application-level gateway.
  • Host-based firewalls, screening router, bastion hosts, and the DMZ in a distributed deployment.
  • Today: the NGFW (DPI, app/user awareness, IPS, TLS inspection) is the baseline; the WAF defends the HTTP layer (OWASP).
  • The perimeter distributes to cloud and host; Zero Trust and microsegmentation frame the perimeter firewall as one layer, not the whole defense.
Hands-on

To absorb remaining time: write a minimal default-deny nftables ruleset (or AWS Security Group) allowing SSH and HTTPS, or explore a firewall console on a lab VM.
