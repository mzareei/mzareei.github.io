Malicious Code (Malware)

Viruses, worms, trojans, rootkits, botnets, APTs and ransomware — how they work, how they hide, and how we defend against them.

Instructor: Mahdi Zareei Viruses · Worms · Botnets · Ransomware · APTs

What is malware?

The NIST 800-83 definition

"A program that is inserted into a system, usually covertly, with the intent of compromising the confidentiality, integrity, or availability of the victim's data, applications, or operating system or otherwise annoying or disrupting the victim."
— NIST SP 800-83
Link

The definition is anchored in the CIA triad from Week 1: malware is simply software designed to violate one or more of those three principles.

01

Classifying malware

Two key questions: does it need a host? does it replicate?

Two classification axes

How malware is classified

Axis 1 — Does it need a host?

  • Parasitic: needs a host program (e.g. viruses). Embeds itself in legitimate code.
  • Independent: self-contained standalone program (worms, trojans, bots).

Axis 2 — Does it replicate?

  • Non-replicating: trojans and spam — activated but don't self-copy.
  • Replicating: viruses and worms — make copies of themselves to spread.
Also

First classify by how it spreads to reach its targets; then by the actions or payloads it performs once it arrives.

The full tree

The malicious-software family

Needs a host (parasitic)

  • Trap doors / backdoors — secret entry point
  • Logic bombs — "explode" when a condition is met
  • Trojan horses — useful outside, harmful inside
  • Viruses — infect a program by modifying it
  • Browser plug-ins / extensions, scripts

Independent

  • Worms — actively seek out more machines to infect
  • Botnets — networks of compromised machines under attacker control
  • APTs — advanced persistent threats, targeted and stealthy

Click to reveal each branch. Modern ransomware (covered later) combines several of these mechanisms.

Host-needing types

Trap doors, logic bombs & trojans

🚪

Trap door / backdoor

A secret entry point to a program or system. Typically triggered by recognizing a special input sequence or a specific user ID.

💣

Logic bomb

Code embedded in a legitimate program that "explodes" or runs a malicious action when certain conditions are met (a date, a firing, a missing file).

🎁

Trojan horse

Hidden inside an apparently useful host program; performs an unwanted or harmful function when the host runs.

Modern term

Today the "trap door" is almost always called a backdoor. They appear both as attacker-introduced entry points and as (sometimes accidental) developer-left ones.

02

Viruses

Like a biological infection: it needs a host to reproduce.

The biological analogy

What a computer virus is

  • Infects a program by modifying it and inserting a copy of itself.
  • Self-copies into the program to spread to other programs.
Analogy

A computer virus is like a biological virus: it cannot reproduce on its own. It must hijack a cell's machinery (a host program) to make copies. With no host to run, it is inert. This distinguishes it from the worm, which we'll see next.

The life cycle

The four virus phases

😴

1 · Dormant

The virus is idle; it will eventually be activated by some event. (Not every virus has this phase.)

⏰

2 · Triggering

Activated to perform the function it was built for. Can be caused by a variety of system events.

🔁

3 · Propagation

Places a copy of itself into other programs or disk areas. The copy may not be identical to the propagating version.

💥

4 · Execution

The function (payload) is performed. May be harmless or damaging.

Anatomy of a virus

Virus structure

Pseudocode
goto main # 1st line: jump to virus main 1234567 # 2nd line: infection flag / marker main:   find uninfected programs   infect them   do_damage()   goto host_program # run normally

Line by line

  • First line: go to the virus "main".
  • Second line: a special flag (infected or not) to avoid re-infecting.
  • Main: find uninfected programs and infect them; do something damaging; jump to the host's first line so it works normally.
  • To evade size-based detection, it compresses/decompresses the host program.
Two ways to classify viruses

By target & by concealment strategy

By target (what they infect)

  • Boot-sector infector — infects the MBR/boot record; spreads when booting from the disk.
  • File infector — infects files the OS or shell considers executable.
  • Macro virus — infects files with macro or scripting code interpreted by an application.
  • Multipartite — infects files in multiple ways at once.

By concealment (how they hide)

  • Encrypted — a portion creates a random key and encrypts the rest of the virus.
  • Stealth — explicitly designed to hide itself from anti-virus software.
  • Polymorphic — mutates with every infection (changes appearance).
  • Metamorphic — completely rewrites itself each iteration; may change behavior and appearance.

Macro & scripting viruses

The document that runs itself

"A virus that attaches itself to documents and uses the macro programming capabilities of the document's application to execute and propagate."
— NISTIR 7298

How it spreads

  • A virus macro is attached to a Word document.
  • The document is opened on the host system.
  • When it runs, the macro copies itself to the global macro file.
  • The global macro activates when new documents are opened.

Why they're dangerous

  • Are platform-independent.
  • Infect documents, not executable code.
  • Are easily spread.
  • Are much easier to write than traditional executable viruses.
The arms race

Why concealment matters: virus vs. AV

→

→

Debate

Every concealment technique exists to defeat signature-based detection. Question: if a virus rewrites itself completely every time, what is left for the AV to detect? (Hint: its behavior — we'll return to this with EDR.)

03

Rootkits

The corrupt building inspector who hides the damage he caused.

Covert, persistent access

What a rootkit is

  • A set of hidden programs installed on a system to maintain covert access to that system.
  • Hides by subverting the mechanisms that monitor and report on processes, files, and registries.
  • Gives the attacker administrator (root) privileges: add/change programs, monitor processes, send/receive traffic, and get backdoor access on demand.
  • Example: hides from the user — not listed in ls or dir.
Analogy

A rootkit is like a corrupt building inspector: it not only permits illegal construction, it falsifies the reports so that, when anyone asks, everything "looks" compliant. The defense sees the doctored answer, not reality.

How it decides what to hide

The rootkit intercepts & filters every call

Intercepted function call
→
Will the call's result reveal the rootkit?
NO →
Pass call to the operating-system function (normal result)
YES →
Execute the call but monitor the result and adjust as necessary (scrub the rootkit out of the answer)
Core idea

The rootkit sits between the program and the OS. If an honest answer would expose it, it edits the answer. Otherwise it lets the real answer through so as not to raise suspicion.

Hiding files in practice

04

Worms

Unlike a virus, a worm moves on its own — no host needed.

The self-propagating threat

What a worm does

  • Actively seeks out more machines to infect; each infected machine becomes a launching pad to attack others.
  • Exploits software vulnerabilities in client or server programs; uses network connections to spread system to system.
  • Also spreads via shared media (USB, CD/DVD) and via email or instant messenger (in attached macros/scripts).
  • On activation it replicates and propagates again; usually carries some form of payload.
Virus vs. worm

A virus is a hitchhiker: it needs you to run a host. A worm is a self-propelled vehicle: it moves across the network with no human help. That's why worms can spread worldwide in minutes (recall WannaCry, later).

Replication mechanisms

How a worm copies itself across systems

Email / instant messengerThe worm e-mails a copy of itself to other systems, or sends itself as an attachment via an instant-message service.
File sharingCreates a copy of itself or infects a file (as a virus would) on removable media.
Remote executionThe worm executes a copy of itself on another system.
Remote file access / transferUses a remote file access or transfer service to copy itself from one system to another.
Remote loginLogs onto a remote system as a user, then uses commands to copy itself to that system.
Target discovery

Scanning: how a worm finds new victims

Scanning (fingerprinting) is the first function of a network worm's propagation phase: it searches for other systems to infect. There are four address-scanning strategies:

Random

Tries random IP addresses. Simple, but noisy and wastes many attempts.

Hit-list

Carries a pre-built list of vulnerable targets for very fast initial spread.

Topological

Uses information on the already-infected machine (address book, known hosts) to find the next target.

Local subnet

Focuses on machines in the same local network, often behind the same firewall.

05

Botnets

An army of compromised machines at the command of a "botmaster".

The attack platform

What a botnet is

  • A bot is a compromised computer under the control of an attacker.
  • The bot code (malware) communicates with the attacker's server and carries out malicious activities per the attacker's instructions.
  • A botnet is a network of bots controlled by an attacker to perform coordinated malicious activities.
  • It is the key platform for most Internet-based attacks and frauds.
Update

Modern case: Mirai (2016) recruited hundreds of thousands of IoT devices (cameras, routers) with default passwords and launched some of the largest DDoS attacks in history. Today much botnet power lives in poorly secured IoT devices.

What they're used for

Attacks & frauds by botnets

Spam

Mass-sending of unsolicited email from thousands of different IPs.

DDoS

Distributed Denial of Service — overwhelm the victim from many machines.

Click fraud

Generating fake ad clicks to defraud advertising networks.

Phishing & Pharming

Hosting and distributing fake pages to steal credentials.

Data / identity theft

Key logging and theft of personal data.

More

Key/password cracking, cheating in online games/polls, and anonymized criminal communication.

How

The attacker orders all bots to flood the victim simultaneously (e.g. a SYN flood). The traffic comes from thousands of legitimate IPs, so it's hard to block without also cutting off real users.

Amplification: little effort, big damage

DNS-amplification DDoS

Attackersends small (~60 byte) DNS requests spoofing the victim's IP
→
Open recursive DNS serversanyone can query; they reply with large records
→

Why it works

A tiny request triggers a giant reply: the "amplification factor" can multiply traffic 50× or more. The attacker spends almost no bandwidth, but the victim drowns. Root cause? Open DNS servers and the ability to spoof the source IP.

Command and control (C&C)

Spreading is easy — but how do you give orders?

The naive plan

  • We build the malware (vx), compile it, and mail it via email / social engineering.
  • Spreading is easy… but what if we want to use the compromised machines?

Orders are needed

There must be command & control (C&C) from the botmaster to the bots. For example: a bot reports its status, is told to download a botcode update, or receives instructions to spam/phish/DDoS.

The core question

Once thousands of machines are infected, how do I talk to them without exposing myself and without letting them shut down my whole operation at once? That question defines C&C design.

Naive approaches vs. robust design

Why C&C is hard to get right

Naive approaches (they fail)

  • Have victims contact us: the vx must include our address (not stealthy).
  • A single rallying point (not robust) and a hard-coded address (not mobile).
  • Contact a single IP/website/ping: easily defeated (ISP intervention, blackhole routing). Only used by beginners.

Good C&C design

  • Efficient and reliable: reach a sizable set of bots within a time limit.
  • Stealthy: hard to detect; blended with normal traffic.
  • Resilient: hard to disable or block.
Today

Modern botnets achieve resilience with peer-to-peer C&C (no central server) and domain-generation algorithms (DGAs) that mint thousands of fresh domains per day to dodge blocking.

◆ Debate

Is a botnet operator more dangerous than a virus writer?

A virus writer releases code and loses sight of it. A botnet operator keeps direct, ongoing control over thousands of machines. Discuss in pairs: who poses the greater threat, and why?

To guide the discussion

There's no single answer. A virus can spread uncontrollably and cause massive untargeted harm; a botnet offers control, flexibility and persistence — reusable for spam today, DDoS tomorrow, crypto-mining next week, even rented out to third parties (crime-as-a-service). Ongoing control is often what turns malware into a business.

06

Advanced Persistent Threats (APT)

The patient predator: it enters, waits, and moves low-and-slow.

Breaking down the term

Advanced · Persistent · Threat

🎯

Advanced

(Special) malware and special operations and operators — resources beyond ordinary cybercrime.

⏳

Persistent

Long-term presence, multi-step, "low-and-slow".

🏛️

Threat

Targeted at high-value organizations and information.

Key difference

Unlike opportunistic malware (which attacks whoever it can), an APT chooses its target and invests months or years. It's not after volume; it's after one specific target.

How they operate

Characteristics of an APT

  • Typically attributed to state-sponsored organizations or criminal enterprises.
  • Distinguished by their careful target selection (business or political).
  • Use social engineering to trick even sophisticated users.
  • Example: first compromise internal routers/servers to learn the valuable targets; then play man-in-the-middle (MITM) to make social-engineering attacks very convincing — even forging answers to suspicious users' challenges.
Historic cases

High-profile attacks: Operation Aurora, RSA, APT1 and Stuxnet.

Low-and-slow & lateral movement

Blending completely into normal activity

Low-and-slow

Carries out its mission — data tampering or exfiltration — slowly to blend with normal activity.

  • Acts only when the target user is authoring and sending a document.
  • Makes repeated small incremental changes to reach the eventual goal.
  • Not a detectable anomaly for existing approaches.

Persistent, multi-step operation

An APT is a persistent operation involving multiple deliberate steps over time, rather than a single attack act.

  • Employs a combination of steps to move laterally through the network.
  • Targets only the necessary systems and users at each attack step.
Today's landscape

Modern APTs: canonical names & cases

Stuxnet (2010)

The canonical nation-state attack on industrial control systems (ICS): it sabotaged uranium-enrichment centrifuges. It crossed from the digital world into the physical.

Pegasus (NSO Group)

A targeted mobile spyware implant: infects phones (sometimes "zero-click") to surveil journalists, activists and officials. The modern, commercial equivalent of the bespoke implant.

Naming today

APT groups are given code names: APT28 / APT29 (linked to Russia), Lazarus (linked to North Korea), among others. Each security vendor uses its own naming scheme for the same group.

07

Ransomware

The dominant malware threat of the last decade — absent from the original material.

Hostage-taking for profit

How ransomware works

1 · Accessphishing, exposed RDP, or exploiting a vulnerability
→
2 · Encryptencrypts the victim's files with a key only the attacker holds
→
3 · Ransomdemands a (crypto) payment in exchange for the decryption key
Business model

Ransomware-as-a-Service (RaaS): developers rent the ransomware to "affiliates" who carry out the attacks and split the profits. This industrialized the crime and lowered the technical barrier to entry.

Extortion escalates

Double & triple extortion

Single

They just encrypt your files. If you have backups, you restore and don't pay.

Double

Before encrypting, they exfiltrate the data. If you don't pay, they publish it on a leak-site. Backups no longer save you.

Triple

Add extra pressure: DDoS against the victim, or threats/direct contact to its customers and partners.

Why it matters

Double extortion changed the rules: good backups are no longer enough, because the attacker also threatens to leak your data. Prevention (keeping them out) becomes paramount again.

Cases that defined the decade

Ransomware: major examples

2017WannaCry — a ransomware worm that used the EternalBlue exploit; spread worldwide in hours.
2017NotPetya — disguised as ransomware, it was really a wiper: it never intended to decrypt anything.
2018+Ryuk — targeted large organizations with high ransoms ("big game hunting").
2020+Conti and LockBit — large RaaS operations with leak-sites.
2023+Clop — exploited file-transfer vulnerabilities (e.g. MOVEit) for mass extortion.
◆ Debate · To pay or not to pay

Should ransomware victims pay the ransom?

A hospital has its systems encrypted; lives are at stake and the backups failed. Do they pay? Argue both sides.

Points for the debate

Against paying: it funds and motivates more attacks; no guarantee you get the data back; it may be illegal if the group is sanctioned. For: sometimes it's the only fast way to restore critical services. Expert consensus: avoid it whenever possible — invest in prevention, offline backups and an incident-response plan so you never face the decision.

08

Modern malware techniques

How today's malware evades traditional anti-virus.

Fileless malware

Living off the land

  • Fileless malware leaves no executable on disk: it lives in memory.
  • Abuses legitimate system tools — LOLBins (PowerShell, WMI, certutil) — to perform malicious actions.
  • Because there's no file to scan, it evades signature-based detection.
Link

This is exactly what drives the shift from signature AV to EDR (endpoint detection & response): if you can't catch the file, you must catch the behavior. We'll see this in the defenses section.

Supply-chain malware

Poison the source, not the victim

Instead of attacking each victim, the attacker compromises a trusted component (an update, a library) that many victims install willingly.

SolarWinds / SUNBURST (2020)

A trojanized network-management software update reached thousands of organizations, including government agencies.

XZ Utils (2024)

A backdoor stealthily inserted into a Linux compression library, nearly reaching worldwide production.

npm / PyPI packages

Package poisoning: uploading malicious libraries or hijacking popular ones to infect whoever installs them.

Link to Week 3

It's so serious that the OWASP Top 10:2025 added a new category: "Software Supply Chain Failures".

The modern zoo

Other types worth knowing

Info-stealers

Steal saved passwords, session cookies, crypto wallets and browser data. Fuel for crime-as-a-service.

Loaders / droppers

Their only job is to gain the first foothold and then download and install the main malware (ransomware, stealer…).

Cryptojacking

Silently hijacks the victim's CPU/GPU to mine cryptocurrency for the attacker.

IoT botnets

Mirai (2016) and its successors recruit insecure IoT devices for massive DDoS attacks.

Lesser-known malware

Four subtler techniques

Clickjacking

Collects an infected user's clicks using transparent or opaque layers so they think they click one thing while clicking another. Keystrokes can also be hijacked.

Malvertising

Places malware on websites without compromising them: the attacker pays for ads likely to appear on target sites and embeds malware in them. Hard to track.

Drive-by downloads

Exploits browser/plugin vulnerabilities: merely viewing an attacker-controlled page downloads and installs malware without the user's knowledge. Doesn't self-propagate like a worm.

Watering-hole

A targeted drive-by variant: the attacker compromises a site the target victim is likely to visit, then waits. The code may infect only the target organization's systems.

And finally…

Unintentional threats

Not every risk is an attacker. These threats aren't malware, but they compromise confidentiality, integrity or availability — exactly what information security protects.

Equipment malfunction

Software malfunction

User error

Failure of communication services

Failure to outsource operations

Loss / absence of key personnel

Misrouting of messages

Natural disasters

Environmental conditions

09

Countermeasures

The ideal solution is prevention; when it fails, detect, identify and remove.

The ideal solution: prevent

Four elements of prevention

📜

Policy

Clear rules on permitted software, devices, downloads and privileges.

🎓

Awareness

Train users: the human link is the most common entry vector.

🩹

Vulnerability mitigation

Patch, harden and reduce the attack surface.

🚧

Threat mitigation

Controls that limit damage even if prevention partially fails.

If prevention fails

Fall back on technical mechanisms supporting three mitigation options: detection (is there an infection?), identification (which malware is it?) and removal (remove it and restore).

The evolution of anti-virus

Four generations of anti-virus

1st · Simple scanners

Require a malware signature. Limited to detecting known malware.

2nd · Heuristic scanners

Use heuristic rules to find probable malware. Also: integrity checking.

3rd · Activity traps

Memory-resident programs that identify malware by its actions, not its structure.

4th · Full-featured

Packages combining several techniques: scanning, activity traps and access control.

Modern continuation

Today endpoint protection continues that line with EDR/XDR (endpoint / extended detection & response), behavior + ML/AI detection and threat intelligence. The standard for describing adversary techniques is MITRE ATT&CK.

From signatures to behavior

Today's defense: EDR / XDR & ML detection

Signatures (classic AV)catches known malware; blind to novel and fileless threats
→
EDR / XDRwatches endpoint behavior in real time and enables response
→
ML / AI + threat intelspots anomalous patterns; updated with shared indicators
ML trade-off

ML detection catches novel, signatureless threats, but at the cost of more false positives: it may flag legitimate software as malicious. Too many false alarms exhaust the security team — the classic "cry wolf" problem.

10

Malware analysis

To defend, you first have to understand what the malware does.

Two approaches

Static vs. dynamic analysis

The goal of analysis is to produce information for detection and response.

Static analysis

Tries to understand what a malware instance would do if executed — without running it. The code is inspected.

Dynamic analysis

Tries to understand what a program does when executed. At different granularities:

  • Fine-grained (e.g. automated unpacking).
  • Coarse-grained (e.g. system-call tracing).
Obfuscation & packing

Packing & unpacking: the obfuscation war

Packing

A technique that compresses, encrypts or transforms part or all of an executable. The code that reverses the transformation is included inside the executable itself, ready to run.

Unpacking

Almost all modern malware comes packed; there are thousands of packers. The volume makes manual unpacking untenable.

  • Automated unpacking that needs no a-priori knowledge is required.
  • Fine-grained tracing-based universal algorithms: detect execution of code not in the packed program's static model.
Run it safely, block it live

Sandbox analysis & behavior-blocking

Sandbox analysis

Run potentially malicious code in an emulated sandbox or virtual machine: a controlled environment where its behavior is observed without threatening a real system.

Enables detection of complex malware: encrypted, polymorphic or metamorphic.

Host-based behavior-blocking

Integrates with the host OS and monitors program behavior in real time, blocking potentially malicious actions before they affect the system. An advantage over signatures/heuristics.

Limitation

Because malicious code must run on the target machine before all its behaviors can be identified, it can cause harm before being detected and blocked. That's why prevention remains the first line.

Takeaways

Summary in one slide

  • There are very many varieties of malicious code — classified by whether they need a host and whether they replicate.
  • A virus needs a host; a worm spreads on its own; a trojan deceives; a rootkit hides; a botnet obeys a C&C; an APT stays low-and-slow.
  • Ransomware is the dominant threat of the last decade (RaaS, double/triple extortion). Modern malware is fileless and targets the supply chain.
  • Defense moves from signatures to behavior: prevention, EDR/XDR, ML/AI and MITRE ATT&CK, plus static and dynamic analysis.
◆ Closing debate

If modern malware rewrites itself and lives in memory, is anti-virus dead?

Polymorphic/metamorphic and fileless malware evade signatures. So does it still make sense to use anti-virus, or should we rely only on behavior + ML detection?

To guide the discussion

Signatures are still cheap and accurate against the huge volume of known malware — a good first filter. Behavior/ML catches the novel, but produces false positives and consumes resources. The answer isn't to pick one: it's defense in depth — signatures + behavior + EDR + prevention + user awareness. No single layer is enough.
